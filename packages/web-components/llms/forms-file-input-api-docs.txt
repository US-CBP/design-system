# cbp-file-input

## Overview

The File Input component builds upon the native file input, allowing for custom styles and enhancing functionality when integrated with JavaScript frameworks. This component should be used within the `cbp-form-field` component like any other input pattern.

## Properties

| Property | Attribute | Description | Type | Default |
| --- | --- | --- | --- | --- |
| `accept` | `accept` | Specifies the files types accepted by the file input (may also be set directly on the slotted input). This property is merely a suggestion to the browser and any file type restrictions should still be enforced in form validation. | `string` | `undefined` |
| `context` | `context` | Specifies the context of the component as it applies to the visual design and whether it inverts when light/dark mode is toggled. Default behavior is "light-inverts" and does not have to be specified. | `"dark-always" | "dark-inverts" | "light-always" | "light-inverts"` | `undefined` |
| `disabled` | `disabled` | Specifies that the field is disabled. Primarily controlled by the parent `cbp-form-field` component. | `boolean` | `false` |
| `enhanced` | `enhanced` | Experimental: Specifies whether the functionality is enhanced over the native web platform file input. This functionality requires integration with a framework or manual handling of the custom events and will not work with a native form post. | `boolean` | `undefined` |
| `error` | `error` | Specifies that the field has an error (and sets aria-invalid accordingly). Primarily controlled by the parent `cbp-form-field` component. | `boolean` | `false` |
| `fieldId` | `field-id` | Optionally specify the ID of the input here, which is used to generate related pattern node IDs and associate everything for accessibility. | `string` | `createNamespaceKey('cbp-file-input')` |
| `multiple` | `multiple` | Specifies whether the file input accepts multiple files rather than a single file (may also be set directly on the slotted input). | `boolean` | `undefined` |
| `name` | `name` | The `name` attribute of the input, which is passed as part of formData (as a key). | `string` | `undefined` |
| `status` | `status` | Supports passing back status and error messages as an array of objects or stringified JSON from the application. The array shall be the same length as the current file list. E.g., [ {"status": "error|success|undefined", "message": "string"}, ... ] One could take the valueChange event's detail.value key, which contains an array of File objects, and add these keys to it before feeding it back to this component via the `status` property. | `any` | `{}` |
| `sx` | `sx` | Supports adding inline styles as an object | `any` | `{}` |

## Events

| Event | Description | Type |
| --- | --- | --- |
| `valueChange` | A custom event emitted when the value of the component changes, either by selecting (non-duplicate) files or canceling the dialog, or clicking the button in the file list to remove a file. | `CustomEvent<any>` |

## Methods

### `getData() => Promise<{ host: HTMLElement; name: string; files: File[]; }>`

#### Returns

Type: `Promise<{ host: HTMLElement; name: string; files: File[]; }>`

### `reset() => Promise<void>`

A custom method to reset the file input component (for enhanced/multi-file inputs) to its initial state and value since it does not update properly on a native form reset. This method may be called manually, but is automatically called on form reset when using the `cbp-form` component.

#### Returns

Type: `Promise<void>`
