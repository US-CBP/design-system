# cbp-treeview and cbp-treeview-item

## Purpose

* The Treeview and child Treeview Item components are used to display information in hierarchical tree, allowing items to be nested within each other recursively.

## Functional Requirements

* Treeview items may be nested recursively with no limit imposed.
* Treeview items with nested children will render an expand control.
* Selectable items will render a checkboxs (after the expand control, if present).
* Selectable parents act like a "select all" for children under them and must be updated based on selections made below them, reflecting a checked, unchecked, or indeterminate state.
* Visual "connectors" are used to display the parent/child relationship of elements in addition to indentation.

## Technical Specifications

### User Interactions

* For Treeview Items with nested children, clicking the expand control will toggle the immediate children between visible and hidden.
* For selectable items, toggling the rendered checkbox may have multiple effects:
  * First, it toggles the checkbox and treeview item selected state.
  * If the Treeview Item is a parent to nested items, it toggles all of those children to the same state as the current checkbox.
  * If the Treeview Item has parents above it, it emits an event triggers those parents to update their states accordingly:
    * If all children are checked, then the parent is checked.
    * If no children are checked, then the parent is unchecked.
    * If some, but not all children are checked, then the parent is in an indeterminate state.
  * Every checkbox toggle triggers the parent `cbp-treeview` to emit a custom `valueChange` event that can be listened to for a rollup of all selected values in the Treeview control.

### Responsiveness

* Labels will wrap where necessary; take care to use short labels to prevent excessive wrapping, even on small screen devices.
* Likewise, care should be take to avoid nesting too deep, so that the control still works on smaller devices.
* If deep nesting and longer label names are unavoidable, consider allowing horizontal scrolling of the `cbp-treeview` component or its container.

### Accessibility

* The parent `cbp-treeview` element:
  * Has a `role="tree"`.
  * If it is selectable it also has `aria-multiselectable="true"`.
  * Should always contain an aria-label (via `accessibilityText` property) if it does not reference an external heading via `aria-labelledby`.
* Each child `cbp-treeview-item` element:
  * Has a `role="treeitem"`.
  * With nested items renders the children inside of container with a `role="group"`.
* Each expand control (button) for items with nested children toggles `aria-expanded` when the control is activated.
* The selection state for each selectable node is indicated with `aria-selected="true"`.

When tabbing into the control to the first expand button or checkbox, the screen reader announces:

* Tree's accessible label (aria-label or aria-labelledby)
* Tree view level [N]
* For expand button: Clickable [treeview item label], button expanded/collapsed
* For checkbox (no children): [treeview/checkbox item label], checkbox checked/unchecked
* When there is no expand button or checkbox to tab to on bottom level (non-selectable) children, cursor navigation can still be used to navigate these items, which will be announced with full treeview semantics as above.
